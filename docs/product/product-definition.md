# 点睛产品定义

## 一句话定位

点睛是面向网页设计、AI 原型和 HTML 演示的浏览器端最后一公里编辑器。它接住已经存在的网页或单文件 HTML，通过 Dock 快速修改和完整工作台精细调整，让非开发创作者像调整 PPT 或 Axure 原型一样，直接在真实渲染结果上完成最后一轮修改。

点睛的正式运行入口是 `apps/dock-extension`。它不是页面重构原型，也不是源码生成器。

## 产品判断：不是画龙，是点睛

AI 编程工具、网页生成器或开发者先把页面内容、结构和交互“画出来”，点睛负责交付前的最后一笔：把已经看得见的页面调准确、调顺手、调到可以展示或交接。

```text
已有网页或 HTML
        ↓
Dock 快速修改
        ↓
完整工作台精细调整
        ↓
离线 HTML / 整页 PNG / AI 与开发交接
```

点睛可以修改、复制、隐藏、移除和重新组织已有页面对象，但不从空白画布生成整套页面，不负责替用户决定内容，也不替代 AI 编程工具和前端开发环境。

## 面向的核心场景

| 场景                       | 用户已经有什么                         | 使用点睛完成什么                                                               | 结果                                   |
| -------------------------- | -------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------- |
| 网页设计与 AI 页面精修     | AI 或开发者生成的网页、落地页、看板    | 直接修改文案、颜色、字体、间距、尺寸和模块位置                                 | 得到可以评审、展示或交接的最终页面     |
| HTML 做演示或“HTML 做 PPT” | 用 HTML 制作的汇报页、演示稿或数据故事 | 在真实画面上调整标题层级、版式、留白、图文位置，并导出离线 HTML 或整页 PNG     | 得到可打开、可分享或可截图汇报的 HTML  |
| 原型精修                   | 已经生成或编写好的 HTML 原型           | 像使用 Axure 一样，通过对象树、画布和属性面板调整对象、布局、尺寸与结构        | 得到更接近定稿的可运行原型             |
| 评审现场修改与开发交接     | 可运行页面和明确的评审意见             | 当场修改、撤销、比较，并把对象、前后值、限制和验收条件整理成 AI 或开发交接信息 | 减少截图、口头描述和源码之间的反复确认 |

“HTML 做 PPT”描述的是用网页技术制作和展示演示内容。点睛当前不生成或编辑 PowerPoint `.pptx` 文件，也不承诺把 HTML 无损转换为 `.pptx`。

## 两种工作形态

### Dock：当前页面里的快速修改

Dock 适合问题明确、改动较小的即时调整。用户不离开当前网页，点中对象就能修改文字、外观和间距，调整层级或可见性，并使用撤销、重做和修改记录放心尝试。

典型任务包括：改一句标题、换一个颜色、调整字号和留白、把 Dock 移开避免遮挡，以及在评审现场立即修正一个可见问题。

### 完整工作台：像 Axure 一样精修已有原型

完整工作台把页面结构树、真实页面画布和属性/布局检查器放在同一界面，适合需要全局视野和精确控制的调整。它支持单选与多选、自由移动与缩放、对齐与分布、统一间距和尺寸、参考线、结构拖动、历史记录，以及本地 HTML 的打开和静态导出。

这里“像 Axure”指选择对象、查看结构、调整属性和布局的操作感觉，不代表点睛拥有 Axure 的从零绘制、组件库、交互逻辑编排或完整原型构建能力。点睛精修已有页面，不负责从空白开始构建内容。

## 正式能力

| 层级       | 能力                                                                     | 交付语义                                              |
| ---------- | ------------------------------------------------------------------------ | ----------------------------------------------------- |
| Dock       | 当前页面选中、文字/外观/间距调整、层级与可见性、撤销重做和修改记录       | 写入当前页面会话或网页副本，不写回站点源码            |
| 完整工作台 | 页面结构树、真实画布、移动缩放、单/多对象布局、结构调整、历史和本地 HTML | 与 Dock 共用页面、选中对象和修改记录，适合复杂精修    |
| 导出       | 离线 HTML 和整页 PNG                                                     | 导出当前渲染结果；不是 `.pptx`，由用户选择保存位置    |
| AI 交接    | 按稳定对象、修改前后值、约束和验收条件生成提示词并复制                   | 用户主动交给开发工具或 AI Agent；点睛本身不执行 Agent |

## 与其他工具的关系

| 工具或方式            | 更擅长的事情                       | 点睛补上的位置                                             |
| --------------------- | ---------------------------------- | ---------------------------------------------------------- |
| AI 编程与网页生成工具 | 从需求生成页面、组件和源码         | 页面已经生成后，由用户直接完成最后一轮视觉判断             |
| Axure、Figma、PPT     | 从空白组织内容、绘制页面或设计交互 | 在真实 HTML 渲染结果上精修，不再重新画一份与实现分离的稿子 |
| 浏览器开发者工具      | 面向开发者调试 DOM、CSS 和运行状态 | 提供更直观、可撤销、可记录和可交接的修改界面               |
| 截图与口头反馈        | 快速指出问题                       | 把“往左一点”等模糊意见直接变成可见结果和具体修改记录       |

点睛不以替代这些工具为目标，而是连接“页面已经做出来”和“页面可以交付”之间的空缺。

## 目标用户

- 使用 AI 生成网页、原型或单文件 HTML，需要自己完成最后一轮调整的产品经理、设计师和运营人员；
- 用 HTML 制作汇报、演示页面或数据故事，希望像调整 PPT 一样直接整理画面的创作者；
- 希望在真实页面上完成评审修改，再把明确结果交给前端或 AI Agent 的协作者；
- 不想为了几个字、颜色、间距和位置反复进入源码，但仍需要修改可追踪、可撤销的人。

## 不承诺的能力

- 不从空白页面生成完整网站、演示内容、组件库或交互逻辑；不以“输入一句话自动建站”为产品方向。
- 不直接修改 React、TSX、Vue 等源码，也不提供服务器端源码回写。
- 不生成或编辑 PowerPoint `.pptx` 文件；HTML 演示的交付物仍是离线 HTML 或整页 PNG。
- 不保证跨域 iframe、Shadow DOM、复杂 Canvas、动态组件或无法读取资源的完整编辑。
- 不上传页面内容，不提供账号、云端数据库、云端同步或内嵌 Agent。
- 普通 HTTP(S) 页面需要用户主动输入地址并授予对应站点权限；网页副本修改不等于修改原站点。

## 成功判断

产品成功不以功能数量判断，而以用户能否在已有页面上完成一条闭环判断：发现问题、直接选中、调整到位、撤销或确认、导出或交接。

每项优化使用统一状态：`已规划 → 已实现 → 已验证 → 已验收 → 已发布`。其中“已验证”要求代码或测试证据，“已验收”要求真实浏览器或用户确认，“已发布”要求版本 tag、GitHub Release 和 ZIP 产物。
