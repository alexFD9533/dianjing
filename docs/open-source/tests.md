# 测试覆盖与发布门槛

## 现有检查入口

| 检查       | 命令                     | 作用                               |
| ---------- | ------------------------ | ---------------------------------- |
| 类型检查   | pnpm typecheck           | 检查 workspace TypeScript 项目     |
| 单元测试   | pnpm test                | 执行当前仓库测试                   |
| Dock 构建  | pnpm build:dock          | 生成正式 MV3 产物                  |
| Dock 回归  | pnpm test:dock:e2e       | 验证构建产物和页面内 Dock          |
| 工作台回归 | pnpm test:dock:workspace | 验证画布、对象树、布局和导出主路径 |

## 必须覆盖的负向行为

- 未授权页面和浏览器内部页不注入；
- 不稳定或重复定位目标不写入；
- 普通网页不被宣称为源码回写；
- 导出失败时不生成缺资源的“成功”文件；
- Dock、选框、参考线和滚动位置在截图后恢复；
- 提示词生成不执行 Agent，也不上传页面内容。

## 发布门槛

Alpha 发布至少需要在干净环境完成依赖安装、类型检查、单元测试、格式检查、构建和 Chromium E2E。仅有静态构建通过不能替代真实浏览器验收；本地无法使用 Chromium 时，应在 GitHub Actions 中完成并保留日志。
